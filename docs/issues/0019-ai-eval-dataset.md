# AI eval dataset: hand-authored cases and frozen Weather Briefs for the recommendation calls

## Description

The two Claude calls in `src/lib/ai` — Crop Recommendation (`recommendCrops`) and Variety
Recommendation (`rankVarieties`) — are the product. Today nothing tells us whether an
answer is _good_, only whether it parsed: the unit tests assert the tool-call plumbing
against a stubbed SDK, and the only judgement of the actual agronomy is a human reading the
wizard. Before the demo we want a fixed set of inputs whose correct answers we can state up
front, so a prompt or model change can be checked against something other than a vibe.

This issue delivers the **dataset only — there is no runner**. Cases are hand-authored
data plus assertions; wiring them to a harness that actually calls the model is a separate,
later task. The value here is that the expectations exist, are reviewed, and are frozen
alongside inputs that cannot drift.

The dataset lives under `evals/` at the repo root:

- `evals/README.md` — what a case is, how to read the constraint vocabulary, how to run one
  by hand until a runner exists.
- `evals/cases/*.json` — the cases: a Field Profile, a Weather Brief reference and a date,
  plus the constraints a correct answer must satisfy.
- `evals/briefs/*.json` — the frozen Weather Briefs the cases point at, one file per brief.

Roughly **20 Crop Recommendation cases** and **6 Variety Recommendation cases**, spread
over the agro-zones, the Soil Classes, both irrigation answers, the land-size buckets and
the three sowing seasons (spring, autumn, off-season).

Each case carries **constraint assertions** rather than a golden answer — the model may
phrase and order things differently and still be right:

- `mustInclude` — crop / variety ids that have to appear in the ranked list.
- `mustExclude` — ids that must not appear (wrong season, wrong soil, no irrigation).
- fit ordering — pairs `[a, b]` meaning `a` must be ranked above `b`.

On top of the per-case constraints, four **global invariants** hold for every case:

1. The answer is a schema-valid tool call (the tool is called, its arguments parse).
2. The candidate rule is respected: every recommended Crop is in `candidateCropIds(today)`.
3. The prose is Romanian plain text and the variety names are real names from the Crop
   Dictionary — no invented cultivars, no English, no markdown.
4. `fit` is strictly descending across the ranked list, and `confidence` is not `high` on a
   low-data case.

**Weather Briefs.** Six briefs are captured for real from Open-Meteo on 2026-09-13, one per
agro-zone anchor location: Reviga (Ialomița, Bărăgan plain), Cobadin (Constanța, Dobrogea),
Dăbuleni (Dolj, Oltenia sands), Lovrin (Timiș, Banat plain), Turda (Cluj, Transylvanian
plateau) and Podu Iloaiei (Iași, Moldavian plain). Because a real brief can only exist for
the day it was captured, the seasons the demo cares about are covered by three **synthetic**
briefs — 2026-03-05, 2026-10-05 and 2026-08-20 — derived from `weatherBriefFixture` with
forecast temperatures normalised to the month normals, and labelled `"kind": "synthetic"` so
no one mistakes them for observations. The capture script is committed
(`scripts/capture-eval-briefs.ts`, `bun run capture:eval-briefs`) so the briefs can be
re-cut for a later date.

**Out of scope / known gap.** ADR 0002's source-quoting rule — that a recommendation cites
the Crop Dictionary field it leans on — is _not_ asserted by this dataset. Encoding it needs
a per-field provenance map the cases do not have. Noted here so the gap is deliberate rather
than forgotten.

**Test exemption.** The dataset is data and documentation with no runtime surface: nothing
imports `evals/`, no route, procedure or component changes. Per AGENTS.md rule 3 this task
is exempt from unit and e2e tests. The one piece of code, `scripts/capture-eval-briefs.ts`,
is a developer script excluded from `tsc`; it is verified by running it and validating every
brief it writes against `weatherBriefSchema`.

## Acceptance criteria

- [ ] `scripts/capture-eval-briefs.ts` is committed and wired as
      `bun run capture:eval-briefs`; re-running it overwrites the briefs in place.
- [ ] `evals/briefs/` holds nine brief files: six `"kind": "captured"` (Reviga, Cobadin,
      Dăbuleni, Lovrin, Turda, Podu Iloaiei) with `capturedAt` and `"source": "open-meteo"`,
      and three `"kind": "synthetic"` for 2026-03-05, 2026-10-05 and 2026-08-20 with
      `generatedAt`, `"source": "fixture"` and a `notes` field saying what was derived.
- [ ] Every brief's `brief` field parses against `weatherBriefSchema`.
- [ ] `evals/briefs/SUMMARY.md` is generated by the script and lists, per brief: today,
      forecast day 0 tMax/tMin, total forecast rain, the last month's temperature and
      precipitation anomaly, the number of drought-flagged years and the outlook labels —
      plus the `candidateCropIds` list for each case date.
- [ ] `evals/cases/` holds ~20 Crop Recommendation cases and ~6 Variety Recommendation
      cases, each naming a Field Profile, a brief slug and a date, with `mustInclude`,
      `mustExclude` and fit-ordering constraints.
- [ ] The four global invariants are written down once in `evals/README.md` rather than
      repeated per case.
- [ ] `evals/README.md` explains the case format, the constraint vocabulary, the
      captured/synthetic distinction and the ADR 0002 source-quoting gap.
- [ ] `CONTEXT.md` gains glossary rows for **Eval Case**, **Captured Brief** and
      **Synthetic Brief**.
- [ ] `CHANGELOG.md` has an entry, and the PR description states the rule 3 exemption.
- [ ] Gate green: typecheck, lint, prettier, Vitest. No e2e (nothing to exercise).
